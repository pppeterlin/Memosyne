# v0.7 — The Open Threshold

> 主題：讓陌生人 10 分鐘內把 Memosyne「跑起來、看到價值、決定要不要長期用」。
> 內部複雜度不動；所有改動都對外可見。

## 動機

v0.4–v0.6 把 Memosyne 從「個人腳本集合」演化成「能正確處理累積型來源的記憶基礎設施」。引擎成熟了，但**對新使用者的門檻仍然高**：

- 裝完 `pip install -e .` 後沒有「下一步做什麼」的明確指引
- README 從神話世界觀講起，30 秒看不到產品價值
- 9 個 Muses、Tapestry、Chronicle、Slumber、Ordeal、Aletheia… 概念量壓垮初次閱讀
- Ollama / OpenRouter / DeepSeek 三種 provider 沒有「一鍵切換」的指令
- 部份核心操作（enrich / contextualize / naming）必須 `cd Personal_Brain_DB/00_System` 直接呼叫 .py
- 錯誤訊息深度不一致，常常 stack trace 而非「下一步該做什麼」

v0.7 是 **polish for adoption** release。不引入新演算法、不擴張功能集，把現有能力磨到 OSS 公開時讓人「想用」。

## 設計原則

| 原則 | 翻譯成行為 |
|------|----------|
| **30 秒看到 demo** | README 第一段就是 `pip install + memosyne quickstart` → 出現搜尋結果 |
| **預設可工作，進階可調** | 每個 env var / config 都有合理 default；用戶不用配置就跑得起來 |
| **錯誤訊息 = 下一步指引** | 每個 fail 都告訴你「該做什麼修」，不是 stack trace |
| **神話是裝飾不是門檻** | 公開介面用工程詞彙；神話保留在輸出細節、命名彩蛋、AGENTS.md |
| **CLI 是 source of truth** | 任何 `cd 00_System` 直接跑 .py 的需求都是 bug |

## Workstream

### WS1 — The Threshold Ritual（首次體驗）

新指令 `memosyne quickstart`：

- 偵測可用 LLM provider（Ollama 跑著？OpenRouter key？DeepSeek key？）
- 沒有就提示「pick one: A/B/C」並把對應 setup 指令印出來
- 用 `sample_vault/` 做 demo：rebuild 索引 → 跑 3 個 example search → 印結果
- 印出「想用自己的記憶？把 .md 丟進 spring/ 然後 `memosyne ingest`」收尾

**出口**：clean machine `pip install -e . && memosyne quickstart` 5 分鐘內看到搜尋結果。

### WS2 — The Hand of Memory（CLI 一致性）

把 daily 操作的所有 `cd 00_System` 補進 memosyne CLI：

- `memosyne enrich [--file PATH] [--model M]` — passthrough enrich.py
- `memosyne contextualize` / `memosyne hyqe` — passthrough vectorize.py with flag
- `memosyne tapestry --rebuild` 已存在但要驗證 docs 同步

CLI behavior 修正：

- `memosyne rebuild` 預設增量；`--full` opt-in（目前永遠 full）
- `memosyne search --return-parent` 旗標；或自動展開短 snippet
- `memosyne search` snippet 縮排 + 顏色提升可讀性
- vectorize progress 改 tqdm（停止 21K 行洗版）
- ingest 對 Gemini-export 自動偵測「裸檔名 + 同 dir 有 hash 兄弟」→ 提示或自動補

**出口**：常見 daily 操作完全不需要 `cd Personal_Brain_DB/00_System`。

### WS3 — The Oracle's Whispers（錯誤訊息升級）

每個 fail 都升級成 diagnostic + actionable next step：

```
[fail] Ollama API http://127.0.0.1:11434/api/tags
       reason: connection refused
       next: brew install ollama && ollama serve &
             or use --provider deepseek (see memosyne providers)
```

- `memosyne health --fix` 模式：能自動修的（建目錄、拷 example config、init artifact 目錄）直接做
- ephemeral artifact（`dirty_paths.txt` / `query_log.jsonl`）absent → `ok` 而非 `warn`
- LLM call 失敗時印出「使用的 provider/model」幫助 debug

**出口**：用戶遇到任何 fail 都能在錯誤訊息裡找到修法，不用查 docs。

### WS4 — The Codex Visible（文檔重組）

- README 改寫：
  - 第一屏（不滾動）= 30 秒 demo + 3 行價值聲明
  - mythology 移到「Why Memosyne / The Mnemosyne Inspiration」獨立 section
  - 加 1 張 architecture diagram（mermaid 淺色背景）
  - 加 1 張 data flow diagram（Spring → Discernment → Weaving → Inscription → Search）
- `docs/` 重組三層：
  - `docs/getting-started/` — 5 分鐘 install + demo
  - `docs/using/` — 日常操作（ingest / search / correct / slumber）
  - `docs/architecture/` — 內部設計（給 contributor / 想 hack 的人）
- **Glossary 對照表**：mythology 詞彙 ↔ 工程詞彙（"Calliope = AI chat router"，"Chronicle = access log"…）

**出口**：陌生人 10 分鐘讀完知道 Memosyne 是什麼、能幹嘛、怎麼開始。

### WS5 — The Many Springs（多 provider 一鍵切換）

借鑑 gbrain `providers list`：

```bash
memosyne providers list
# ollama       (local)     gemma4:26b loaded   ✓ working
# openrouter   (cloud)     key present         ✓ working
# deepseek     (cloud)     key present         ✓ working
# proxy        (local)     not configured      —

memosyne providers test deepseek
# → 跑一次 hello-world LLM call，回報 latency / cost / model

memosyne init --provider deepseek
# → 寫 .env + memosyne.toml 設好 LLM_PROVIDER=deepseek + 推薦模型
# → memosyne health 預期全綠
```

每個 provider 對應一份 recipe doc（`docs/providers/<name>.md`）列：env vars、預設模型、價格區間、限制、何時用。

**出口**：用戶選一個 provider 一條指令配好；不用讀 llm_client.py 源碼。

### WS6 — The Rite of Release（release script）

- `scripts/release.sh X.Y.Z`：bump pyproject → commit → tag → 生成 release notes 草稿 → push
- pre-push hook：tag 前自動跑 `make verify`，沒過不讓 tag
- `make release-notes vX.Y` 從 `git log` 自動生成 changelog draft（標題、commit 列表、co-author）
- CHANGELOG.md 從 commit message 半自動 sync

**出口**：「忘記 tag v0.5」這種事不會再發生；contributor 看到 release 流程清楚就敢提 PR。
