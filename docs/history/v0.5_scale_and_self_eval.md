# v0.5 規模化、自我評估與外部接觸面

## 目的

v0.4 解決「能被公開」的問題（privacy、sample vault、MCP smoke、eval --sample）。
v0.5 解決「能持續變強」的問題——讓 Memosyne 在真實使用下持續累積、自我量測、並能被遠端 agent 安全接觸。

對標研究：gbrain（v0.32，garrytan/gbrain）。
它是同一象限的開源專案（個人記憶 + agent + hybrid retrieval + skill 系統），
17,888 pages / 4,383 people / 723 companies、21 個 cron job、Postgres-native。
它在以下幾個面向值得我們直接借鑑，
但 Memosyne 的神話世界觀、PPR + ACT-R + Tapestry + Slumber 認知架構是我們的差異化，
**不該為了對齊而稀釋。**

---

## gbrain 值得借鑑的優點

### 1. Zero-LLM 確定性連結抽取

gbrain `src/core/link-extraction.ts` 用純 regex 從 markdown 抽取
`[Name](path)`、`[[slug]]`、`[[source:slug]]` 三種 entity reference，
完全不呼叫 LLM。
每次 `put_page` 後自動 post-hook 建邊。
Memosyne 目前 Tapestry 的邊主要靠 Oracle LLM 抽，
LLM 失誤就斷邊。

### 2. Eval capture-replay（contributor mode）

`GBRAIN_CONTRIBUTOR_MODE=1` 開啟後，每次真實 `search` / `query` 會（PII scrub 後）寫入 `eval_candidates`。
`gbrain eval export` 凍結 baseline，改完 code 後 `gbrain eval replay` 跑回放，
輸出三個數字：Mean Jaccard@k、Top-1 stability、latency Δ。
**Off by default，contributor 才打開。**
這是「真實使用 → 回放保護線」的範式，比我們現在純合成 golden set 強。

### 3. Backlink-boosted ranking

`hybrid.ts::applyBacklinkBoost`：score × `(1 + 0.05 × ln(1 + backlink_count))`，
在 cosine re-score 之後、dedup 之前。
被多次連結的記憶有溫和加權，幾乎零成本，效果穩定。

### 4. Two-pass 結構檢索

`search/two-pass.ts`：用 keyword/vector 找 anchor → 在 graph 上走 N hop（capped at 2、每 hop ≤50 個鄰居）→ 鄰居分數 = anchor_score × 1/(1+hop)。
比 PPR 輕，可以作為 PPR 之外的快速路徑。

### 5. Salience + recency 細粒度 boost

`applySalienceBoost`（emotional_weight + take_count）、
`applyRecencyBoost`（per-prefix half-life decay map）。
我們有 Chronicle（ACT-R）但都是全域，沒有 per-directory 衰減：
日記 / 知識頁的時間敏感性不同，分開設半衰期才合理。

### 6. Dream cycle 8 階段 maintenance

`gbrain dream`：lint → backlinks → sync → synthesize → extract → patterns → embed → orphans。
synthesize 把對話 transcript 用 cheap Haiku verdict cache 過濾後，
fan-out Sonnet subagent 凝成 originals/concepts/reflections。
我們 Slumber 已經有 reflect / hebbian / forget 三階段，
可以再加 transcript-synthesize 與 orphan-detect。

### 7. Provider 抽象 + recipe

`gbrain providers list` 列出 14 個 embedding provider（OpenAI / Voyage / Gemini / Azure / DashScope / Zhipu / Ollama / llama.cpp / LiteLLM / …），
每個有 env var、預設維度、定價、限制矩陣。
`gbrain init --pglite --model voyage` 一鍵切換。
我們目前 README 已經與 Ollama 解耦，但缺一個顯式 recipe 表。

### 8. MCP HTTP + OAuth 2.1 + admin dashboard

`gbrain serve --http` 內建 OAuth 2.1（client credentials、auth code + PKCE、refresh、revocation），
30 個 operation tag 為 `read | write | admin`，
`sync_brain` / `file_upload` 標記 `localOnly` 在 HTTP 上一律拒。
embedded React admin dashboard 65KB gzip 直接打包進 binary。
我們目前只有 stdio MCP。

### 9. CI 自動 invariant 檢查

`scripts/check-privacy.sh`、`check-jsonb-pattern.sh`、`check-progress-to-stdout.sh`、
`check-test-isolation.sh`、`check-admin-scope-drift.sh`。
每條規則寫成一支 shell script，`bun run verify` 串起來。
我們 v0.4 已有 Dockerfile clean-install，但沒有
「掃描公開檔案是否殘留真實人名 / 私有路徑」這類靜態守門。

### 10. 評測公開化（LongMemEval、BrainBench）

`gbrain eval longmemeval <dataset.jsonl>` 直接跑 HuggingFace 公開資料集
（in-memory PGLite per run、TRUNCATE 之間、不動真實 brain）。
公開 benchmark 是建立信任的最便宜方式，
我們可以 wire 起 LongMemEval 跑 sample vault 之外的維度。

## 與 Memosyne 的對齊與差異

| 面向 | gbrain | Memosyne 現況 | v0.5 取捨 |
|---|---|---|---|
| 圖譜 | typed link（zero-LLM 抽 + post-hook） | Tapestry + LLM enrichment | 借抽取機制，保留 LLM enrichment 作為補強而非主路徑 |
| 認知衰減 | 全域 recency boost + half-life map | Chronicle ACT-R（已實作） | 加 per-directory 半衰期，把「日記 / 知識 / 對話」分開 |
| 圖譜遊走 | two-pass walk（淺、快） | PPR spreading（深、準） | **兩者並存**：two-pass 給互動式查詢，PPR 給 deep search |
| 評測 | golden + capture-replay + LongMemEval | Eternal Mirror + Augury | 加 capture-replay（opt-in）+ LongMemEval wrapper |
| 儲存 | PGLite / Postgres + pgvector 單引擎 | Chroma + Kuzu + SQLite | **不動**：v0.5 不做引擎重構，工程成本不划算 |
| MCP | stdio + HTTP + OAuth 2.1 | stdio | 加 HTTP 模式（local-only token，OAuth 留 v0.6） |
| Skill | 34 skill + RESOLVER | 1 個 memosyne-invocation | 補 ingest / search / correction / slumber skill |
| Provider | 14 recipe，CLI 可列 | README 描述，無 CLI | 加 `memosyne providers list/test` |
| Always-on | signal-detector 每訊息 | 無 | 留待 v0.6，MCP HTTP 穩定後再做 |

## v0.5 主題

1. **The Self-Weaving Tapestry** — 連結抽取從 LLM-only 變成 deterministic + LLM 雙路。
2. **The Augury Replay** — 真實查詢回放，retrieval 改動的安全網。
3. **The Refined Chronicle** — per-directory 衰減 + backlink boost + two-pass walk。
4. **The Open Threshold** — MCP HTTP（local token）+ provider registry CLI。
5. **The Codex of Skills** — fat skill 文件擴張到 5–8 個。
6. **The Vigil of Invariants** — CI 靜態守門，防止公開資料外洩 / 規範漂移。

---

## Workstream 1: The Self-Weaving Tapestry

### 動機

Tapestry 邊目前只由 Oracle LLM 在 enrich 時寫入。LLM 漏抽 / 改名 / 不一致 → 圖譜稀疏。
加一條確定性路徑後，LLM 變成「補強」而非「唯一來源」。

### 任務

- [ ] `00_System/link_extractor.py`：純 regex 抽取
  - markdown link `[Name](10_Profile/.../slug.md)`、`[[slug]]`、`[[type:slug]]`
  - frontmatter 中的 `people:` / `locations:` / `events:` list
  - 段落內的 `@person-slug` / `#event-slug` 短記
- [ ] `ingest.py` / `enrich.py` 每次寫 YAML 後呼叫 extractor，
      直接寫入 Tapestry（不經 LLM）。
- [ ] LLM enrichment 路徑變成「補強」：只在 deterministic 抽不到時才呼叫，
      或用 LLM 做「實體規範化」（alias → canonical slug）。
- [ ] `tapestry.py --rebuild --deterministic-only`：用純 regex 重建一次完整圖，
      作為 baseline。
- [ ] 比較 deterministic-only vs deterministic+LLM 的邊數與召回。

### 出口

- 重建後 deterministic 邊 ≥ 70% 現有 LLM 邊覆蓋
- 一次 vault 全量重建 < 30 秒（不含 LLM）
- `tapestry --stats` 區分 `edges_deterministic` 與 `edges_llm`

## Workstream 2: The Augury Replay

### 動機

Eternal Mirror（HyQE round-trip）+ Augury（golden）保住正確性下界，
但無法回答「我這次改 retrieval、現實使用會不會被打亂」。
真實查詢回放補上這層。

### 任務

- [ ] `mneme_weight.py` 已記 access log。擴 schema：
      新增 `query_log(ts, query_text, detail, retrieved_slugs[], latency_ms, source)`，
      `source ∈ {mcp, cli, eval}`。
- [ ] 預設 **opt-out**：
      `MEMOSYNE_CAPTURE_QUERIES=1` 才寫，或在 `memosyne.toml` `[eval] capture = true`。
      （與 gbrain 一致：contributor 才開，但允許在 privacy.md 明確說明後預設打開 sample vault。）
- [ ] PII scrub pipeline：移除 query 中的 email / phone / 私有人名（用 vault profile 已知人名清單反向遮罩）。
- [ ] `memosyne eval export --since 7d > baseline.jsonl`
- [ ] `memosyne eval replay --against baseline.jsonl`，輸出：
      - Mean Jaccard@k between 過去 / 當下 retrieved_slugs
      - Top-1 stability
      - latency Δ
      - 前 N 條 regression（Jaccard 最低）
- [ ] privacy.md 加一段「Query Log Capture」說明開關、scrub 規則、刪除路徑。

### 出口

- sample vault 跑得通：`memosyne eval --sample` 後 7 天能 export 出非空 baseline
- replay 後三個數字會印出來
- 一條真實 regression 能在 top-N 列表中被指出

## Workstream 3: The Refined Chronicle

### 動機

ACT-R 全域衰減對 30_Journal（時間敏感）與 50_Knowledge（時間中性）一視同仁，
不合理。Backlink boost 與 two-pass walk 是極低成本的補強。

### 任務

- [ ] `mneme_weight.py` 加 per-prefix half-life：
      ```toml
      [chronicle.decay]
      "30_Journal/" = { half_life_days = 90 }
      "20_AI_Chats/" = { half_life_days = 60 }
      "50_Knowledge/" = { half_life_days = 0 }   # evergreen
      "10_Profile/" = { half_life_days = 0 }
      "40_Projects/" = { half_life_days = 180 }
      ```
- [ ] `search.py` 在 cosine re-score 後、ACT-R 重排前加：
      - backlink boost：`score × (1 + 0.05 × ln(1 + inbound_edges))`
      - 鄰居數從 Tapestry 取，不另存
- [ ] 新增 two-pass walk path：
      - anchor = 三路 RRF top-K（K=10）
      - 在 Tapestry 走 1–2 hop，鄰居 score = anchor × 1/(1+hop)
      - 與 PPR 並存：`--walk fast`（two-pass）/ `--walk deep`（PPR，現行）
- [ ] Augury 跑回歸：把 walk 開 / 關、boost 開 / 關，
      確認每個 toggle 都在 golden set 上有可解釋的 delta。

### 出口

- backlink boost 在 golden set 上 nDCG@10 ≥ 持平
- per-prefix decay 讓「最近的日記」對話 query 排序明顯前移，「常識性筆記」不被誤降權
- two-pass walk 在 60% 查詢上比 PPR 快 ≥ 5×，Jaccard@10 ≥ 0.8

## Workstream 4: The Open Threshold（MCP HTTP）

### 動機

stdio MCP 只能本機 Claude Desktop / Cursor 用。Cloud agent（OpenAI、Perplexity、自己跑的 server）連不上。
v0.5 提供 **local-only token-based HTTP**，OAuth 留 v0.6。

### 任務

- [ ] `mcp_server.py` 抽 transport：stdio vs http，操作集相同。
- [ ] `memosyne serve --http --port 7777`：
      - 預設只 bind `127.0.0.1`
      - token 從 `~/.memosyne/tokens.sqlite` 讀，SHA-256 hash 儲存
      - `memosyne auth create <label>` / `auth list` / `auth revoke <label>`
- [ ] Operation scope tag：每個 MCP tool 標 `read | write | admin`。
      ingest、enrich、slumber 標 `write`；correction 標 `admin`。
      token 可指定 scope。
- [ ] `localOnly` 標記：`memosyne correct apply` 等破壞性操作在 HTTP 上一律拒。
- [ ] 文件 `docs/mcp.md` 加 HTTP 設置與 ngrok / Tailscale 提示，
      明確警告「不要在公網 expose 沒 OAuth 的 HTTP」。

### 出口

- 本機 `curl -H "Authorization: Bearer ..." http://127.0.0.1:7777/...` 通
- Claude Desktop 用 stdio、Cursor 用 stdio（不變），第三方 agent 用 HTTP
- Augury 在 HTTP 模式下可跑

## Workstream 6: The Vigil of Invariants

### 動機

公開後最怕「不小心 commit 真實人名 / 真實路徑 / 私有 vault 片段到 docs/」。
v0.4 已有 sample vault 與 privacy.md，但靠人工。v0.5 把它變 CI。

### 任務

- [ ] `scripts/check_no_real_paths.sh`：
      掃 `docs/`、`README*`、`AGENTS.md`，攔截 `/Users/<name>/`、`/home/<name>/` 形式（除非在 fenced block 且標註 `# example`）。
- [ ] `scripts/check_no_private_names.sh`：
      從 `_private_terms.txt`（gitignored）讀禁字清單，
      `git diff --cached` 命中即 fail。
- [ ] `scripts/check_sample_vault_synthetic.sh`：
      確認 `sample_vault/` 內所有 `.md` 的 entity 都在 `sample_vault/_synthetic_entities.yaml` 白名單中。
- [ ] `scripts/check_docker_clean.sh`：
      build image 後 `find / -name "*.md" | xargs grep -l "<真實私有 token 樣式>"`，無命中才通過。
- [ ] `Makefile` `make verify` 串起以上 + 現有 health。
      GitHub Actions（v0.6 才開 public CI）先寫好 workflow YAML。

### 出口

- `make verify` 全綠才能 tag release
- 任何想 push 公開 branch 的 diff，pre-push hook 跑 check_no_private_names
- privacy.md 更新章節「Static Invariants」說明這些守門

## 不做的（明確排除）

- **儲存引擎重構**：不換到 PGLite / Postgres + pgvector。Chroma + Kuzu + SQLite 工程成熟，換引擎是 v1.0 才該談的決定。
- **OAuth 2.1 + admin dashboard**：v0.5 只做本機 token，公網 expose 與 OAuth 留 v0.6。
- **Always-on signal-detector**：MCP HTTP 沒站穩前不做 ambient capture，會把日誌灌滿垃圾。
- **Code-aware retrieval**（tree-sitter / code-callers）：Memosyne 是個人記憶，不是 code KB。除非有人提需求否則不做。
- **34 個 skill**：fat skill 是好框架，但每個 skill 維護成本不低。先做 5–6 個能跑完整流程的就停。

## 出口標準（v0.5 完成條件）

1. Tapestry 邊有 ≥ 70% 來自 deterministic 抽取，LLM 退到補強角色
2. `memosyne eval replay` 能在 sample vault 上跑出三個數字
3. backlink boost、per-prefix decay、two-pass walk 三個 toggle 都有 Augury 報告
4. `memosyne serve --http` 本機可用，token 管理 CLI 完整
5. `00_System/skills/` 有至少 5 個 SKILL.md，RESOLVER 覆蓋所有公開 CLI 動詞
6. `make verify` 包含 ≥ 4 條公開資料 invariant 檢查
7. CHANGELOG 與 README 更新；docs/v0.5_*.md（本文件）與 docs/evaluation.md 串接

完成這六條後，Memosyne 從「能被公開」進化為「在公開使用下能自我量測並持續變強」。
這是個人記憶基礎設施的真正分水嶺。
