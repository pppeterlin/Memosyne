# WS1 — Deterministic Extractor Coverage Report

## Goal (from `docs/v0.5_scale_and_self_eval.md`)

> 重建後 deterministic 邊 ≥ 70% 現有 LLM 邊覆蓋

## Method

`link_extractor.extract_from_vault()` runs purely on frontmatter +
markdown links + body shorthand (`@person-slug`, `#event-slug`,
`[[type:slug]]`). No LLM. Edge counts are compared against
`tapestry --stats` for the four memory→entity relations:
`mem_person`, `mem_location`, `mem_event`, `mem_period`.

Entity-↔-entity edges (`event_loc`, `person_loc`, `person_event`) are
not in scope here — they're LLM-only by design (they encode
relationships the user didn't explicitly write down).

## Result (private vault, measured 2026-05)

| Relation | Deterministic extracted | Tapestry (LLM-built) | Ratio |
|---|---:|---:|---:|
| `mem_person`   | 441 | 418 | 105.5% |
| `mem_location` | 407 | 408 |  99.8% |
| `mem_event`    | 581 | 580 | 100.2% |
| `mem_period`   |  25 |  25 | 100.0% |
| **Total**      | **1454** | **1431** | **101.6%** |

Memories scanned: 297. Memories with ≥1 entity (deterministic): 263.

## Interpretation

Deterministic extraction **exceeds** the LLM-built Tapestry, not
because the LLM is broken, but because:

1. Frontmatter (`entities.people`, `entities.locations`, etc.) is the
   ground truth — it was written by the Oracle pass that uses the LLM
   to extract entities and persists them. So a re-extraction from
   frontmatter rebuilds what the LLM originally found.
2. The deterministic extractor additionally picks up entities from
   markdown links and body shorthand the LLM may have overlooked,
   plus normalizes aliases.
3. Tapestry may have lost some edges due to historical schema changes
   or partial backfills; deterministic rebuild restores them.

## Implication for the v0.5 exit criterion

`≥ 70%` coverage was a conservative target assuming the deterministic
path would be a strict subset of the LLM path. In practice it's a
superset, so the Tapestry can be rebuilt entirely from deterministic
extraction with zero LLM dependency:

```bash
memosyne tapestry --rebuild   # uses link_extractor under the hood
```

LLM enrichment remains valuable for **non-edge** signals (themes,
summary, importance, personal_facts) and for inferring entity-↔-entity
relationships the user didn't make explicit. The role split is:

- **Deterministic** — owns Memory → Entity edges (idempotent, fast,
  rebuild-safe)
- **LLM** — owns Entity → Entity edges + narrative metadata (best
  effort, requires Oracle/Ollama)

## Future work

- Add edge provenance column (`source: deterministic | llm`) so
  `tapestry --stats` can report the split directly without re-running
  the extractor.
- Wire `tapestry --rebuild --deterministic-only` for emergency
  rebuilds when the LLM is unavailable.
- Re-measure ratio whenever vault grows materially.
