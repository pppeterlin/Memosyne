# v0.8 — The Distant Forge

> 主題：把運算外包給遠端鍛造爐；Mac 只做主奉禱者（編排 / 介面 / vault 持有）。

## 動機

v0.4–v0.7 把 Memosyne 磨成「能用、能擴展、能採用」。下一步是**讓日常使用不再讓 Mac 燙**。

兩個明確決定（v0.7 結束時定案）：

- **LLM 全部走 DeepSeek 雲端**（v0.6 已支援 deepseek provider，v0.7 已支援 `providers list`）
- **Embedding 走遠端 GPU server**（Windows WSL + Ollama，4070 Super，LAN/Tailscale）

Mac 退回成編排層：CLI 入口、vault 真相、MCP server、search 即時回應。所有 LLM/embedding 算力外包。

## 為什麼這版值得獨立 release

兩個 user-facing 變化是不相容的設計決策：

1. **Embedding 後端可插拔**——之前 hardcode 在 `vectorize.py` 的 `SentenceTransformerEmbeddingFunction`，現在要支援多 backend + env 切換
2. **Health / provider 表面要涵蓋 remote endpoint**——光看 Ollama 是 `up` 不夠，要看 embedding endpoint 是 `up`

外加 v0.6 留下的 **Phase 3 partial enrichment**（v0.7 也 deferred 過一次）；這次再不做就會變心理債。

## 設計原則

- **預設行為不變**：未設定 `MEMOSYNE_EMBED_PROVIDER` → 跟 v0.7 一樣跑本地 sentence-transformers
- **失敗顯式**：remote endpoint 不通就 fail，不要 silently 降級到本地（會讓 batch embed 突然慢 50×）
- **embedding model 一致是契約**：切換 backend 必須用同 model name 或顯式 migrate
- **不動 vault**：vault 永遠在 Mac；不要為了「集中算力」把 vault 也搬到 server

## Workstream

### WS1 — Remote embedding backend

實作於 `vectorize.py`：

- 新增 `RemoteEmbeddingFunction(chromadb.EmbeddingFunction)`：
  - 支援兩個 protocol：
    - `ollama` (POST `/api/embeddings`)
    - `openai-compat` (POST `/v1/embeddings`，TEI / OpenAI / 自架 OpenAI proxy 都吃這個)
  - Batch 模式：把 N 個 doc 包進一次請求（避免每段一個 HTTP RTT）
  - Timeout + retry（指數 backoff）
  - 連不通時：**fail-fast 報錯**（不靜默降級到本地）

- env 切換：
  ```
  MEMOSYNE_EMBED_PROVIDER=local | ollama | openai-compat
  MEMOSYNE_EMBED_URL=http://windows.tail-xxxxx.ts.net:11434
  MEMOSYNE_EMBED_MODEL=nomic-embed-text         # ollama 用名稱
                                                # tei 用 model_id
  MEMOSYNE_EMBED_DIM=768                        # 顯式宣告，避免 silent dim mismatch
  ```

- 預設 `local` → 跟 v0.7 完全一致；改 env 才走遠端

**驗收**：`memosyne rebuild --full` 在 Mac 端 CPU 平靜、Windows GPU 跑滿、速度 ≥5×

### WS2 — Provider 偵測擴張

`memosyne providers list` 從只看 LLM 擴張成 LLM + embedding 兩段：

```
── LLM providers ────────────────────────────────────────
ollama       local        — no models loaded
deepseek     cloud        ✓ env LLM_API_KEY (35 chars)
openrouter   cloud        ✓ file openrouter-key (73 chars)

── Embedding providers ──────────────────────────────────
local-st     local        ✓ paraphrase-multilingual-MiniLM-L12-v2
ollama       remote       ✓ nomic-embed-text @ windows.tail-...:11434
openai-compat remote      — MEMOSYNE_EMBED_URL not set
```

`memosyne providers test embed` 跑一次 hello-world embed call、報 latency + dim。

### WS3 — Health check 涵蓋 remote endpoint

`memosyne health` 在 `MEMOSYNE_EMBED_PROVIDER=remote` 時：

- ping 該 endpoint（GET `/api/tags` for ollama / GET `/health` for tei）
- 連不到 → `[fail]` + 明確 next-step：
  ```
  [fail] embedding endpoint http://windows.tail-...:11434
         reason: connection timeout (3s)
         next:  1. tailscale status         (確認 mesh 健康)
                2. ssh user@windows && systemctl status ollama
                3. or unset MEMOSYNE_EMBED_PROVIDER to use local fallback
  ```
- 連到但 dim 跟 `MEMOSYNE_EMBED_DIM` 不符 → `[fail]` + 提示「跑 `memosyne embed migrate`」

### WS4 — Migration helper

```bash
memosyne embed migrate --to nomic-embed-text --url http://windows.tail-...:11434
# → 確認 endpoint 可達
# → 跑一個 sample embed，回報 dim
# → 比對現行 Chroma collection 的 dim
# → 不符就：
#     - 印出預估時間（依現有 chunk 數）
#     - 確認後跑 vectorize --rebuild + 切換 .env
```

避免你手動 `--full` 切錯 model 撞牆。

### WS5 — `docs/deployment/distributed.md`

完整 recipe，分四段：

1. **Windows / WSL 端準備**——nvidia-smi 通、Ollama 在 WSL 內裝、`ollama serve` daemonize、`ollama pull nomic-embed-text`
2. **Networking**——Tailscale 設定（推薦）vs LAN port forward；如何拿到穩定的 endpoint URL
3. **Mac 端 `.env` 配置**——三個 env var；`memosyne embed migrate` 跑一次；驗證 `memosyne providers test embed` 綠
4. **故障排除**——GPU 沒通、port 沒開、Tailscale 重連、latency 突然飆高、Chroma dim 不一致

### WS6 — Phase 3 partial enrichment（v0.6 deferred）

讓 enrich 在 `_try_turn_aware_*_update` 路徑下只處理新 turns：

- 把現有 enrich 抽出來：`enrich_text(text, prior_enrichment=None)` 接受可選的舊 YAML
- 對新 turns enrich → 與舊 YAML merge（field-level union/append/max 規則）：
  - `locations / people / events / emotions` → set union
  - `themes` → set union，top-N 截斷
  - `personal_facts` → append（事實是時序的）
  - `importance` → max（高不該被稀釋）
  - `period` → frozen after first write
  - `summary` → 重新生成（包含全文，不只新 turns）
- `ingest._try_turn_aware_gemini_update` 不再 `_clear_enriched_at`，改 mark 為「partial-pending」
- `enrich.py` 識別 partial-pending、只處理 diff、寫回 merged YAML

**驗收**：247-Gemini 中找一個已 enriched 的對話，append 5 個 turn 再 ingest → enrich 階段只 LLM call 1 次（不是整檔 re-process）

## 範圍外（明確不做）

- **vault 也搬遠端**——vault 是 Mac local source of truth，不動
- **search query embedding 也走遠端**——query 是 single-shot, 走網路反而慢
- **Chroma DB 也搬遠端**——本機讀寫快，沒理由搬
- **Public exposure of Windows endpoint**——假設 Tailscale 或 LAN，不做 OAuth / TLS
- **TEI Docker 部署 first-class 支援**——文檔提到，但官方推 Ollama 路徑
- **新 LLM provider**——v0.7 的 4 個夠用

- 不影響 v0.5 retrieval 凍結；只是運算位置改變、結果完全一致
